# Kotoba (Nihongo Tracker 5)

The app is called **Kotoba** on the home screen (`name`/`short_name` in `public/manifest.webmanifest`, plus `<title>` and `apple-mobile-web-app-title` in `index.html`). The icon is a black brush-ink 言 on washi paper with a red sun. It is rendered by the opening animation's own shader at the moment the animation hands over to the app, so icon and opening always match. `node scripts/make-icons.mjs` regenerates the brush outlines (`src/ink/glyph.js`), the ink simulation (`public/ink/`) and the icons. An icon already on a phone's home screen doesn't update by itself: remove it and add the app to the home screen again.

A homescreen web app (PWA) for learning Japanese: spaced repetition (FSRS) for kana, kanji and vocabulary, interactive grammar lessons that adapt to the words you know, stats, and sync between devices.

## Put it online (GitHub → Vercel, as before)

1. Open your GitHub repo `p3seid3n/nihongo-tracker` in the browser. Delete the old files (or just upload over them), then drag **the contents of this folder** (not the folder itself, and without `node_modules` / `dist`) into the repo and commit. The build step removes leftovers of the old version by itself.
2. Vercel redeploys automatically. Settings stay the same (Framework: Vite, build `npm run build`, output `dist`).
3. On your phone: if the old app still shows, close it fully and reopen. If it is stuck, remove it from the home screen and add it again (Safari → Share → Add to Home Screen), or clear the site data for the domain once.

The app works fully without step "Cloud sync" below. Everything is stored on the device.

## Cloud sync and login (free, about 3 minutes)

The easy way, all inside Vercel:

1. Vercel → your project → **Storage** → **Create / Connect** → **Supabase** (free plan). Accept the defaults. Vercel creates the Supabase project and adds its settings to your project's environment variables.
2. Deployments → **Redeploy** (so the build sees the new variables).
3. In the app: Settings → Account and sync → Sign in or create account. The first time it syncs, the app creates its own table through a small Vercel Function (`api/setup-sync.js`); you don't open the Supabase dashboard.
4. If the confirmation email's link doesn't open the app: Supabase → Authentication → URL Configuration → set **Site URL** to your Vercel address. (Or switch off "Confirm email" there.) This is the one thing the integration can't do for you.

How it works: the integration adds `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` (or `..._PUBLISHABLE_KEY`), which the build reads (`envPrefix` in `vite.config.js`, `src/lib/cloudEnv.js`), and `POSTGRES_URL_NON_POOLING`, which only the server function uses. When sync finds no table, the app calls `/api/setup-sync` once; the function runs the statements in `api/_schema.js` (the same as `supabase.sql`, a test keeps them identical) and the request is retried. It only ever creates that one table, and does nothing when it already exists. Supabase hosts the database and logins; it doesn't host the app, so the app stays on Vercel.

The manual way (any host, or if you prefer): create a project at supabase.com, run `supabase.sql` in the SQL editor, then set `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` in Vercel and redeploy.

The anon key is meant to be public. Your data is protected by row-level security: each account can only see its own rows.

## Importing your Anki decks

Settings → Backup and import (or the button on Today). Pick the `.apkg`. Parsing happens on the device; a 146 MB export took about one second in testing.

* If you export from Anki with **"Include scheduling information"** ticked, your progress is kept (FSRS stability and difficulty are read when present).
* Your current export has no scheduling. For each deck enter how many cards you already know, in order (e.g. RRTK 315, Kaishi 41). They come back for a quick check spread over 10 days.
* An imported Hiragana/Katakana deck pauses the built-in one so you don't study both.
* **Pictures:** mnemonic pictures (Tofugu kana decks) and illustrations (Kaishi) are kept and shown on the back of the card. They are stored on the device together with the audio (the same "Include audio and pictures" switch). If you imported a deck before 4.9, import the same file again once: the pictures are added and your progress stays.
* **Deck options:** the wizard offers to take over your Anki deck options: FSRS parameters (if you optimised them in Anki), desired retention, learning and relearning steps, maximum interval and easy days.
* **Audio:** if the deck has recordings (Kaishi has word and sentence audio), the wizard offers "Include audio". The clips are unpacked into the browser's own storage (about 2,900 clips for Kaishi, a minute at most) and play instead of the built-in voice. Importing the same file again later adds audio to a deck you already imported without touching your progress. Audio stays on that device and is not synced; Settings → Listening and speaking shows the size and can remove it.

## Back to AnkiDroid (export)

Settings → Backup and import → Export to Anki (.apkg). Pick the decks; the file holds every card with its reading, per-kanji furigana, meaning, example sentence, notes, your own mnemonic, audio and pictures, and (optional) your progress: due dates, intervals, repetitions, lapses, suspended cards and each card's FSRS memory state (stability, difficulty, last review), plus the review history and a "Kotoba" deck-options preset with your FSRS parameters and retention. A word's recall card becomes the second card ("Recall") of the same note. Open the file with AnkiDroid. If the same decks are already in AnkiDroid, delete them first or import into a new profile, otherwise each card is there twice. Switch FSRS on in AnkiDroid so it uses the memory state. Tested by importing an export of a real collection (4,066 notes) into Anki 26.09: every note, card state, review and file imported, and Anki reads the same stability and difficulty. `src/lib/exporter/anki.js`.

## How it works

* **Scheduler:** FSRS-6 as in Anki/AnkiDroid: the same default parameters (until 4.8 the app used an older set where a first "Easy" meant 16 days instead of 8), the same formulas (`tests/fsrs-reference.test.js` checks 4,800 random steps against ts-fsrs, the reference implementation; the export test checked them against Anki 26.09), elapsed time counted in study days like Anki (from the last review to the next 4 am), Anki's fuzz, the load balancer (within the fuzz range a card goes to the day with the fewest reviews), easy days, learning steps (default 1m 10m) and relearning steps (10m) written like Anki's, a maximum interval, same-day reviews through FSRS's short-term formula, and burying: a word's recognition and recall cards never come up on the same day. All in Settings → New cards and reviews → Scheduling. Your own optimised weights: Memory model.
* **Today (the daily plan):** a curated list for the day, built in `src/lib/plan.js` from a weekly rhythm. Cards come first, every day. Around them one to three other kinds of practice rotate through the week (Mon grammar and reading, Tue writing and sentences, Wed grammar and a writing prompt, Thu reading and pitch, Fri grammar and sentences, Sat writing, prompts and reading, Sun pitch and grammar). The list is trimmed to your minutes per day (Settings → Daily plan); what does not fit moves to "If you have time". Finished items are ticked from the activity log. Anything unavailable (no pitch data, too few sentences, a track switched off) is skipped.
* **New grammar pace:** a new lesson appears only every N days (Settings → Daily plan, default 7). The first 8 lessons (writing, です, は, が, the two adjective kinds, verbs, negatives) are easy, so with "Early lessons are quicker" on they come every N/3 days (every 2 days at the default). Lessons marked "already known" don't count as learned for the pace. On grammar days between lessons the slot holds a review or sentence practice, and the next lesson can always be started early ("Get ahead" under "If you have time", or the Grammar tab).
* **Practice tab:** every kind of practice in one list (cards, writing characters, grammar review, sentence practice, reading, writing prompts, pitch practice). Locked ones say what they need.
* **Settings:** a menu of pages (Daily plan, New cards and reviews, Cards and decks, Memory model, Listening and speaking, Look and feel, Backup and import, About). The card library lives under Cards and decks.
* **Lessons:** 45 lessons in the order of Tae Kim's Guide (CC BY-NC-SA 3.0, personal non-commercial use with attribution). Explanations and example sentences are written for this app. Practice sentences are generated from a word bank and weighted towards words you are shaky on. Lessons are scheduled with FSRS too, so grammar comes back for review. Units can be tested out of. Most pages carry a reference table (`src/content/tables.js`, plus the tables written into the lessons). The toggle under a lesson's title switches between the Kotoba explanation and Tae Kim's: his text is not copied into the app, the Tae Kim view links to the matching section on guidetojapanese.org (needs a connection) and lists what the lesson covers. Matching exercises work from either column, and after an answer the full sentence is shown with word glosses, a translation and audio.
* **Kanji font:** Settings → Look and feel. Classic (the system's Mincho, default), Clear (Noto Sans JP) and Textbook (Klee One). The two extra fonts are SIL OFL, copied from the `@fontsource` packages into `public/fonts/` by `scripts/build-fonts.mjs` (runs on build), split into small slices and fetched the first time they are needed, then cached for offline use.
* **Layout:** full-screen views (study, lessons, import) never scroll as a whole page; only their content area does, so the top bar and the answer buttons stay put, and the page behind sheets is locked. Lesson and exercise buttons sit in their own footer below the scrolling content.
* **Leaving:** closing a full-screen view animates the view you were on (it stays mounted until it has left); sheets slide away when removed by their parent; lesson pages slide from the right going forward and from the left going back.
* **Furigana on cards:** a vocabulary card's answer puts the reading over each kanji (手[て]伝[つだ]う) instead of under the word. The reading is lined up with the spelling (kana in the word match kana in the reading), and a run of several kanji is split using how those kanji read in your other words, allowing for sound changes (rendaku, っ). Readings are laid out invisibly from the start, so the word doesn't move when the answer appears. `src/lib/furigana.js`.
* **Furigana in sentences:** shown only for kanji you have not learned yet (kanji cards you graduated, plus kanji in well-known words). Change in Settings.
* **Sync:** offline-first. Each part of your data (settings, decks, progress per deck, review log per month) is merged by timestamp, so two devices never overwrite each other's reviews. Signing in on a device that already has data asks whether to combine or replace.
* **Motion:** follows Material 3 Expressive. Movement of things (cards, sheets, the nav pill, bars) uses springs that overshoot slightly; fades and colour use springs that settle without bounce. The spring curves are generated as CSS `linear()` easings (`npm run springs` regenerates `src/springs.css`). Sheets can be dragged down and settle with the speed of your finger. Settings → Animations → Reduced (or your device's reduce-motion setting) turns it down.
* **Haptics:** every control ticks; switches rise when turned on and fall when turned off; turning a card over is a tick-tock; Again is a heavy double knock, Hard one firm knock and an echo, Good a crisp pair, Easy a rising run; combos, the blade slash, quests, achievements and a new rank each have their own; finishing builds up to a thud. Patterns live in `src/lib/haptics.js`. Android (Chrome, Brave) can only switch the motor on and off, so the feel comes from pulse length and rhythm. **5.0 fix:** 4.8 shortened the pulses to 4–10 ms for crisper taps, and many phones (Samsung Galaxy in particular) simply drop pulses that short, so haptics went silent. Every pattern is now stretched to what the motor can play before it is sent (`shape()`: each pulse at least 26 ms, gaps at least 48 ms, rhythm kept; Settings → Look and feel → Strength: Light 16 ms, Normal 26 ms, Strong 38 ms). "Try haptics" also says whether the browser accepted the vibration. iPhone Safari 17.4+ has no vibration API, so a hidden switch control is toggled to get the system tick. Desktop browsers don't vibrate.
* **Design (Settings → Look and feel → Design):** Material You (the original solid, tonal surfaces; the default) or Liquid glass. Liquid glass is real refraction, not just blur: each glass element (dock, sheets, toasts, the answer panel, the study screen's buttons) is treated as a slab of glass (n = 1.5) with a convex squircle rim. For every pixel near the rim the slope of the surface is turned into a sideways shift of the light with Snell's law; that field is drawn into a displacement map (red = x, green = y) per element and size, with the element's real corner radii, and fed to an SVG `feDisplacementMap` through `backdrop-filter: url(#…)`. Red, green and blue are shifted by slightly different amounts (dispersion), giving the faint rainbow fringe on the rim, and a second map holds the specular highlight where the rim faces the light. Maps are redrawn when an element changes size (`ResizeObserver`), elements are picked up as they appear (`MutationObserver`). A slow wash of the palette's colours moves behind the page so the glass has light to bend. Only Chromium browsers (Chrome, Brave, Edge, Samsung Internet) can put an SVG filter in `backdrop-filter`; Safari and Firefox get frosted glass instead. `src/lib/liquidGlass.js`, `src/glass.css`.
* **The dojo (gamification):** experience points for everything you do (Again 1, Hard 2, Good/Easy 3, +2 for a new card, ×1.5 for recall cards, repeats 1; lessons 20–35 by score, other practice 12–26; combo bonuses from 5 in a row). XP is worked out from the review log itself, so it is identical on every device and needs nothing extra synced (`src/lib/game.js`, folded incrementally so it stays fast with large imported histories). Ranks run like a martial-arts dojo from 十級 (10th kyū, white belt) through 一級 to 初段 (shodan, black belt, 4,000 XP) and up to 十段; the obi of the samurai on Today takes your belt colour. A daily XP goal (Casual 20, Regular 50, Serious 100, Intense 200), three daily quests picked from the date (the same on every device, only ones you can do), 18 kanji achievements (初 first answer, 連 7-day streak, 剣 combo of 25, 侍 every grammar lesson…), the best combo and the longest streak (Stats → top). New ranks get a ceremony (a scroll unrolls with the rank brushed on it, taiko, the samurai raises his sword); achievements, quests and the day's goal get a banner, during a session too. Which celebrations a device has already shown is the only thing kept locally.
* **Feel:** a correct answer cuts a blade slash across the card (two crossing cuts on Easy), XP floats up, the combo counter (連) climbs, and at 5, 10, 15, 20, 25… a 連撃 combo banner with a full-width cut and the ring of a katana. Wrong answers shake the card. Finished sessions and lessons throw sakura petals and count up the XP earned against the day's goal and the next rank. The samurai (an original character) greets you on Today with a Japanese saying (with romaji and English), worries late in the day when your streak is at risk, hops when the goal is reached, and does a flourish when tapped. `src/ui/Dojo.jsx`, `src/lib/fx.js`, `src/dojo.css`.
* **Sound:** every sound is synthesised on the device with Web Audio, no recordings: koto and shamisen are Karplus-Strong plucked strings (the shamisen with its buzzing sawari), taiko a falling-pitch drum with the stick's thump, the katana an air whoosh plus inharmonic ringing steel, fūrin and rin bells with beating partials, a breathy shakuhachi with vibrato, hyōshigi clappers. Melodies use the miyako-bushi scale; consecutive right answers climb it note by note. Optional background music: slow generative koto phrases with a low string drone, quieter while words are read aloud, paused in the background. Settings → Look and feel → Sound (effects on by default, music off, volume, try buttons). `src/lib/sound.js`.
* **Opening animation (ink in paper):** 言 is brushed onto washi paper and the ink soaks outwards through the paper's fibres; a drop of vermilion spreads into the sun; then the ink floods out of the strokes over the whole page, which becomes the app's background.
  * The movement is simulated ahead of time (`scripts/ink-field.mjs`): the brush follows KanjiVG's centre lines with pen pressure and dry-brush streaks; ink spreads from the wet line through a paper of random absorbency and long kozo fibres (a shortest-arrival-time search), and spreads with the square root of time (Washburn's law), so it rushes out and then crawls. The result is two small textures in `public/ink/`: when the ink reaches each point and how much pigment arrives.
  * A WebGL shader (`src/splash/renderer.js`) turns that into the picture every frame: glossy black where the brush is, a feathered, granulating fringe, wet paper that dries, the sun's darker dried rim. On top of that, time itself slows down: full speed when the brush lands, then about a third (`inkTime` in the renderer).
  * It is drawn in a Web Worker on an OffscreenCanvas, so it stays smooth while the app's code is loading on the page. Without OffscreenCanvas it draws on the page; without WebGL the app just opens. `vite.config.js` inlines it into `index.html` so it starts before the app bundle.
  * It takes about 1.2 s plus a 0.6 s flood, only on a cold start. Reopening within a minute, reduced motion (Settings → Look and feel, or the phone's setting) or a tap skips it.
* **Ink highlights:** the brand character on the welcome and sign-in screens is drawn stroke by stroke, headings are brushed in, Today's card has a faint ink wash and finished screens get a red seal (`src/ui/Ink.jsx`, `src/ink.css`).
* **Still dock:** the page itself never scrolls; the content scrolls inside a fixed container (`.app-scroll`). Browser toolbars only hide and return when the document scrolls, which used to resize the screen under the dock.
* **Answers and explanations:** after Check, a panel at the bottom says Correct or Not quite. Drag it up (or tap its handle) to see why: what went wrong (a particle swapped for another and what each one does, a missing or extra word, the verb not at the end, a particle cut off from its word, a verb conjugated as the wrong type with the rule to make the form, a form that doesn't match the English tense), the corrected sentence, the full sentence with audio, and a word-by-word breakdown. A built sentence whose noun phrases are in another valid order counts as correct, with the usual order shown. `src/lib/mistakes.js`.
* **Word tiles:** tap to add or remove, or drag: into the sentence at any position, within it to reorder, or out again. Tiles slide to their new places.
* **Picking up where you left off:** leaving a lesson or a practice set keeps your place (the page you were reading or the exercise you were on) for a day; the refresh button starts it over. The card session's progress bar counts the whole day, so it doesn't restart at zero when you come back.
* **Motion:** the dock's selection flows between tabs like a drop; pages slide in from the side you moved towards; lists ease in as you scroll (Chrome and Android browsers).
* **Sentence practice:** mixed exercises from the example sentences of cards you have started: match words, pick the meaning, fill the gap, choose the right form of a verb or adjective (or the sentence that matches the English), and build the Japanese from tiles. Every sentence is segmented against your decks (`src/lib/lexicon.js`). A sentence is only used when every word is in one of your decks and at most four words, forms or grammar points are not learned yet; those get a small English gloss above them. Grammar counts as learned once its lesson is done. Tap any word for a popup with reading, meaning, the weakest kanji's story, and a speaker button. Limits: roughly two thirds of Kaishi's sentences are fully explainable; early on, before the grammar lessons are done, many words show glosses and some sentences are skipped; particle-swap questions are deliberately not generated because the wrong particle can still make a valid sentence.
* **Listening:** by default cards read the word when they appear and the example sentence when you reveal the answer. Settings → Listening and speaking lets you read the word on card open, with the answer, or never, and the sentence with the answer or never. Without recordings the phone's Japanese voice is used. If the device has no Japanese voice the app stays silent instead of reading Japanese with the wrong voice; Settings explains how to install one.
* **Pronunciation check:** the microphone button on a card listens through the browser's speech recognition (ja-JP) and compares what it heard with the word or sentence, character by character, with a score. Kanji written in kana by the recogniser still count when the reading is known. Limits: Chrome/Android sends the audio to Google's recogniser, so it needs a connection; Safari and installed iPhone apps may not allow recognition at all, in which case the sheet falls back to recording you so you can compare by ear.
* **Writing practice:** "Write N characters" (Practice tab, and in the daily plan on writing days), plus a pen button on kana and kanji cards. Trace with a stroke-by-stroke guide, or write from memory; strokes must be drawn in the right order and direction (the app says which stroke was expected), with hints and an animated demo. Stroke data is KanjiVG (© Ulrich Apel, CC BY-SA 3.0), built into `public/strokes/` by `node scripts/build-strokes.mjs`, fetched per character when first needed and cached for offline use.
* **Recall cards:** once a vocabulary word has stayed in your memory for 4 days (Settings → New cards and reviews → Start recall after), it also gets a recall card: you see the meaning and give the Japanese. Type romaji or kana (romaji turns into kana as you type; typing the kanji also counts). Exact answers suggest Good, one slip in a word of four or more kana suggests Hard, anything else Again, and you still choose the grade. A recall card is a second schedule for the same word (`deck.key~p` in the same `prog` slice, so it syncs like any other card) with no learning steps. Switch off or limit in Settings. Not built: speaking the answer instead of typing it.
* **Effort budget:** every card costs points once a day (review 1, new card 2, recall review 3, new recall card 4); learning steps and Again repeats are part of finishing that card, so "done" plus "still planned" on Today always adds up to the same day and a day has a budget (Settings, default 200). When it runs out, the rest waits for tomorrow, with "Keep going anyway" if you want more. The Today screen shows the meter. `src/lib/effort.js`, `src/lib/queue.js`.
* **Slow-down for new cards:** new cards (and new recall cards) are scaled down while the due work is more than half the budget (to zero at a full budget) and while recall over the last 7 days is under 80 % (zero under 70 %, with at least 30 answers). Today says how many were held back and why. Asking for "5 more new cards" overrides it. Settings can turn it off.
* **Leech rescue:** after the 8th lapse of a card (then every 4th) a sheet asks for a mnemonic of your own and shows the stories of its kanji and other sentences with the word. The mnemonic is stored as `note` on the card's progress record, shown on the back, and editable from any card (pencil link). Or suspend the card.
* **More sentences per word:** the back of a vocabulary card cycles through its own sentence and others from your cards in which every other word and grammar point is something you already know (`src/lib/sentenceIndex.js`, built in the background when a session opens).
* **Weak spots:** at the end of a session, up to 6 cards you missed twice in the last three days (and that aren't due today) come back once more. Settings can turn it off.
* **Pitch accent:** Kaishi's pitch field is read on import and shown on the back of vocabulary cards (overline, step down, and the pattern name). Decks imported before 4.4 need the same file imported again; progress is kept. Content from another device that has pitch is merged in on sync. 4.6 fixes the reading of words whose markup has a nasal-g mark (いそがしい, ながい: 99 of Kaishi's 1,489 pitch entries were stored with a wrong pattern in 4.4 and 4.5): import the .apkg once more to correct them.
* **Pitch practice (Practice tab):** ten questions from your own decks, only with the original recordings (the phone's voice does not reliably get the accent right, so without audio the screen says how to import it). "Which word did you hear?" uses look-alike words with the same reading and a different accent (橋/箸 style; about 20 pairs in Kaishi's first 1,500 words), "Which melody did you hear?" asks for the pitch drawing of a word. Then Shadowing: listen, record yourself, compare by ear. Pitch itself can't be scored automatically (speech recognition only hears the sounds), so shadowing is by ear on purpose. `src/lib/pitchDrill.js`, `src/ui/PitchPractice.jsx`.
* **Guess first (off by default):** Settings → New cards and reviews → "Guess before you see it". New vocabulary and kanji cards first show only the front with a field for a guess, then the answer with your guess next to it. A wrong guess still helps memory (the pretesting effect) but makes new cards slower.
* **Memory model:** Settings → Memory model. After 400 scored reviews of cards you started in the app (imported "already known" cards have no history), "Fit to my reviews" fits the 21 FSRS weights to your own answers in a Web Worker (about 5 to 25 seconds). A fifth of your cards is kept out of the fit; the new weights are only offered when they predict those cards better by more than the noise, and nothing changes until you press "Use my weights". "Use defaults" goes back; cards already scheduled keep their dates. The weights are stored in settings (`fsrsW`) and sync like other settings. `src/lib/optimize.js` (Adam on numeric gradients, pulled gently towards the defaults), `src/lib/optimizeRun.js`, `tests/helpers/simlog.js` (synthetic review logs used to test it).
* **Reading:** 20 short texts written for this app (Practice tab → Reading), from "My family" to a trip to Kyoto. Each shows a coverage bar: how much of the text is words and grammar you already know. Research suggests about 95–98 % known words for comfortable reading; the texts are short and every new word is glossed, so the shaded 90–97 % band is the target here and "Next up" suggests the unread text closest to it. Tap any word for the reading, meaning and kanji story; new words get a small English gloss above them (switchable); the English translation can be shown per line or for all; every line has its own speaker, and Listen reads the whole text. "New in this text" lists what is not learned yet. "I read it" is stored like a lesson (`read.<id>`) and counts as activity in the effort meter. The texts and their extra vocabulary are in `src/content/reader.js`; the maths is `src/lib/reader.js`.
* **Writing prompts:** 12 prompts (Practice tab → Writing prompts). Write a few sentences (romaji turns into kana as you type, `.` becomes 。), press Check, and the app lists the words and forms you used that you have not learned yet, grammar from lessons you have not done, anything it can't find, and which of the suggested words you used; then it shows one way to say it. It checks what you used, not whether the Japanese is correct (`src/lib/outputCheck.js`).
* **Lexicon changes in 4.5:** 〜たい forms (買いたかった) are understood, adjacent kanji words that the furigana separates (毎朝六時) stay two words, and lesson-bank words typed in kana (がくせい) are found.
* **Backups:** Settings → Export backup (JSON). Restore merges.
